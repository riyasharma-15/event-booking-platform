## Tests failed

No executed check failed. The workflows listed as untested below are blocked by missing test accounts, not recorded as failures.

## Bugs and deployment findings

1. **Test-looking content is publicly visible.** The event listing returned three records, including titles such as “Seat Test Event,” “Organizer 6 Test Event,” and “Valid Title.” Confirm whether these are fixtures and remove or replace them before launch if they are not intended public events.
2. **Default application metadata remains.** Browser pages have the title “Create Next App”; the root metadata description is “Generated by create next app.” Replace these with production branding before deployment.
3. **No automated test suite is configured.** There is no `test` script or installed test runner, so regression checks currently depend on manual testing.

## Security issues discovered

1. **Login throttling not observed — medium-priority hardening gap.** The login handler has no application-level rate limiting or lockout visible in the reviewed code. No brute-force testing was performed; protections at a reverse proxy or hosting edge were not verifiable. Add or confirm effective rate limiting before public launch.
2. No broken access control was confirmed in the unauthenticated checks or reviewed authorization paths. Role-specific and cross-Organizer access denials were not dynamically verified without authenticated accounts.

## Features not tested

The following authenticated or write workflows were not executed to avoid creating or changing database records without dedicated test data:

- Successful attendee registration and login.
- Event booking, viewing persisted bookings, and cancellation.
- Profile edits and profile-picture upload.
- Organizer login, dashboard data, event creation/edit/cancellation, My Events, attendee management, bookings, and Organizer profile updates.
- Admin login, viewing applications, approving/rejecting applications, and role-based denials.
- Attendee-versus-Organizer-versus-Admin API restrictions and cross-Organizer event/attendee/booking isolation.
- Attempts to change a signed-in user’s role or Organizer approval status through the profile API.
- Authenticated rendering of Payments and Revenue and Reviews and Feedback. Source inspection confirms the payment placeholder text and the Reviews Coming Soon state; neither page was reached with an Organizer session.
- Image-upload size/type validation and end-to-end persistence.

## Recommended fixes before deployment

1. Run the full role-based workflow suite in a staging environment with dedicated disposable Attendee, Organizer, Admin, and multi-Organizer fixtures.
2. Add or verify login rate limiting at the application or trusted edge.
3. Remove or relabel test-looking public event records.
4. Replace default page metadata.
5. Add automated tests covering booking/cancellation seat accounting, event ownership, role restrictions, Organizer data isolation, profile field allowlists, and Admin approval/rejection.
